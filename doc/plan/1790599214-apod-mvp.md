# Plan: APOD viewer MVP (no favorites)

Date: 2026-09-28
Derived from: doc/study/1790598821-apod-favorites-app.md

## Scope

Minimum viable app, favorites deferred to a later plan:
- Home page shows today's APOD (title, date, explanation, image/video).
- Any past date can be viewed.
- Every page has nav with login/logout links.
- Seed data + a demo account so a fresh clone isn't empty.
- requirements.txt, .env.example, README covering clone-to-running setup.

Repo is currently empty except CLAUDE.md and the doc/ tree, so this plan scaffolds the whole project. Work happens on a branch off `main` (`feat/apod-mvp`), one conventional commit per checklist group below, then rendezvous back to `main`.

## Checklist

### 1. Project scaffold — `chore: scaffold django project and apod app`
- [ ] Create a virtualenv note in README (not committed) and add `Django` to `requirements.txt`.
- [ ] `django-admin startproject config .` (project package named `config` to keep `manage.py` at repo root).
- [ ] `python manage.py startapp apod`.
- [ ] Register `apod` in `INSTALLED_APPS`.
- [ ] Add `.gitignore` covering `.venv/`, `db.sqlite3`, `.env`, `__pycache__/`, `*.pyc`.
- [ ] Confirm `manage.py runserver 0.0.0.0:8000` boots with the default Django page.

### 2. Config via .env — `build: load secrets from .env`
- [ ] Add a small helper in `config/settings.py` that reads `.env` (simple `KEY=VALUE` lines, `#` comments ignored) and sets `os.environ` values if not already set — no new dependency, since `python-dotenv`/`django-environ` weren't justified in the study.
- [ ] Move `SECRET_KEY`, `DEBUG`, `ALLOWED_HOSTS`, and `NASA_API_KEY` to be read from `os.environ` in `settings.py`.
- [ ] Write `.env.example` listing `SECRET_KEY=`, `DEBUG=`, `ALLOWED_HOSTS=`, `NASA_API_KEY=` with no values.
- [ ] Create a local (untracked) `.env` for development with a real `NASA_API_KEY` from api.nasa.gov.

### 3. APOD data model and NASA client — `feat: add apod entry model and nasa api client`
- [ ] Add `apod.models.ApodEntry`: `date` (unique), `title`, `explanation`, `media_type`, `url`, `hdurl` (nullable), `copyright` (nullable, blank).
- [ ] Add `apod.services` (or similar) with a `get_or_fetch(date)` function: look up `ApodEntry` by date first; on miss, call the NASA APOD API via `urllib.request` using `NASA_API_KEY`, parse the JSON response, save an `ApodEntry`, and return it.
- [ ] Handle and surface API errors (bad key, rate limit, network failure, invalid date) as a typed exception the view layer can catch, rather than letting `urllib` exceptions leak into a 500.
- [ ] Reject dates after today before calling the API.
- [ ] Run `makemigrations` / `migrate` and commit the migration file.

### 4. Views, URLs, templates — `feat: add home and past-date apod views`
- [ ] `apod/urls.py`: `''` → home (today), `'date/<str:date>/'` → detail-by-date, plus a small form/redirect view that takes a submitted date and redirects to the detail URL.
- [ ] Home and past-date views both render the same `apod_detail.html`, branching on `media_type` (`image` vs `video`) in the template.
- [ ] On API/error conditions, render a friendly "picture unavailable" message instead of a 500 page.
- [ ] `base.html` with a nav bar present on every page: Home, "View a past date" (links to a simple date-picker page), and Login/Logout (Logout + username when authenticated, Login when not) — driven by `request.user.is_authenticated`.
- [ ] Wire `django.contrib.auth.urls` under `accounts/` for login/logout, with `LOGIN_REDIRECT_URL` and `LOGOUT_REDIRECT_URL` pointed at home.
- [ ] Minimal `registration/login.html` template (Django's auth view expects this path) extending `base.html`.

### 5. Seed data and demo account — `feat: add seed command with demo account and cached entries`
- [ ] Management command `seed_demo` (idempotent — safe to re-run) that:
  - Creates a demo `User` (e.g. username `demo`, a documented non-secret password) if it doesn't already exist.
  - Creates a couple of `ApodEntry` rows for known past dates so the "view a past date" page has something to show even before `NASA_API_KEY` is configured.
- [ ] Document the demo credentials in the README (not a secret — it's a local demo account, not tied to any real service).

### 6. Admin registration — `feat: register user-facing models in django admin`
- [ ] Register `ApodEntry` in `apod/admin.py` (read-only-ish list view) so admins have visibility; `User` management already comes for free from `django.contrib.auth`.

### 7. Tests — `test: cover home, past-date, and auth nav`
- [ ] Test home view renders using a mocked NASA client (no real network calls in tests).
- [ ] Test past-date view for a valid past date, and rejection of a future date.
- [ ] Test nav shows Login when logged out and Logout when logged in.
- [ ] Run via Django's test runner against the throwaway test DB — never touch `db.sqlite3`.

### 8. Docs — `docs: add readme with setup steps`
- [ ] README covering: clone, create/activate venv, `pip install -r requirements.txt`, `cp .env.example .env` + fill in `NASA_API_KEY`, `python manage.py migrate`, `python manage.py seed_demo`, `python manage.py runserver 0.0.0.0:8000`, demo login credentials, where to get a NASA API key.

### 9. Rendezvous
- [ ] Open a PR / merge `feat/apod-mvp` into `main`.
- [ ] After merge, run migrations + `seed_demo` + `runserver 0.0.0.0:8000` from a clean checkout to confirm the "clone to running" path actually works as documented.
- [ ] Sync `doc/wiki/` to describe the shipped app (models, views, env vars, seed command) as its own follow-up step per the workflow.

## Explicitly out of scope (deferred)

- Favorites model, favoriting action, and favorites page (next plan).
- `requests` dependency (stdlib `urllib.request` is sufficient per the study).
- Any styling/JS beyond plain server-rendered templates.
